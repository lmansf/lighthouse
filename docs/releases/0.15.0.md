# Lighthouse 0.15.0 — a chat and its files

**The vault is gone.** Lighthouse used to be a folder of your documents plus an
explorer for toggling which of them the AI could read. It is now one thing:
**attach up to ten files to a chat and ask about them.** Everything attached is
in scope, nothing else is, and attaching a file IS the decision — there is no
tree to curate, no per-file toggles, and no folder being watched.

This is the trade the release makes on purpose: a smaller product, done far
better. Retrieval, extraction, the column catalog and the index all run at
**attach** time now, so the first question after a drop is already warm.

## What changes for you

**Your files are not touched.** Nothing is moved, renamed, or deleted.
Attaching copies the bytes into the app's own store; the originals stay exactly
where you keep them.

**Your old vault folder is left alone.** The app simply stops reading it. Its
contents are still yours, still on disk, exactly as they were. The app's own
state from that era (`.rag-vault/` — the index, the extraction cache, the
inclusion flags) is also left in place, untouched and unread; delete it when
you are confident you don't want to roll back.

**Your model, your keys, and your chat history carry over.** Nothing about
sign-in, providers, sealed keys, or saved chats changes.

## What went away

Each of these existed to serve a durable, curated corpus. Without one, none of
them has a subject:

- **The file explorer** and the whole tree: sources, folders, link-in-place,
  move / rename / new folder, remove-to-trash and undo.
- **Inclusion.** Files were excluded by default and became searchable only when
  their own toggle was on and no ancestor folder was excluded. Now: attached, or
  not.
- **Curation rules** — the per-folder predicate layer that decided matching
  files, present and future.
- **Local-only marks** ("Private — this device only"). This is a real reduction
  in per-file control and worth saying plainly: you can no longer mark ONE file
  as never-to-the-cloud while a cloud model answers over the others. The gate is
  now the ask's own provider choice — pick the private model and nothing about
  any attached file leaves this device. Two honesty notes retire with the marks:
  "N files skipped — marked private", and "…is in your vault but not included".
- **Investigations, boards, pins, saved views, the semantic layer, and
  briefings** — the durable-analysis features layered on the vault.
- **The filesystem watcher.** Nothing changes underneath the app any more.
- **Auto-exported chat notes.** Chats were written back into the vault as
  indexed notes so later asks could recall them. Chat history is ordinary local
  UI state again; the history panel is the whole story.
- **The onboarding vault step and the default-inclusion step.** First run is one
  screen: welcome and pick a model.

## What is new or better

- **Attach is the moment of work.** Extraction, chunking, the column catalog and
  the retrieval index all warm on attach, keyed by content hash. Re-attaching a
  file you have used before finds every cache warm.
- **An exact, portable answer cache.** Cached answers key on the attachments'
  content hashes instead of an `mtime:size` heuristic over a whole folder. Two
  chats holding byte-identical files share a cached answer; one changed byte is
  a miss. In the vault era, any change anywhere invalidated everything.
- **Exports go where you say.** Saving a chat, a result CSV, an evidence pack or
  the audit log now opens your OS save dialog instead of writing into an app-
  chosen folder.
- **Managed policy `vaultRoots` still works** — it now constrains which files may
  be **attached**, which is the same question it always meant.

## Under the hood

- `workspace.rs` ⇄ `workspace.ts`: a content-addressed blob store plus one
  manifest per conversation. Ids are `att-` + the first 12 hex of
  sha256(content hash + name), so the same bytes under the same name are the
  same attachment in every conversation, in both engines.
- The retrieval RANKER moved to `retrieval.rs` ⇄ `retrieval.ts` and no longer
  knows what a corpus is — a caller hands it items and it ranks them.
- Caps: **10 files** per conversation, **25 MB** per file, both refused at the
  engine with the reason the UI shows verbatim.
- The perf gate changed subject to match the promise: a FULL conversation
  (10 files, ~1 MB each) must ingest in seconds and answer a warm query in well
  under half a second.

## Upgrading

Nothing to do. Install over the top; your model, keys and chats are preserved.
Downgrading to 0.14.x also works — that build will find its old vault state
exactly where it left it.
